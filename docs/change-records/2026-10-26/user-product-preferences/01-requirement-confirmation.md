# 01 — 需求确认记录

日期：2026-10-26 ｜ 分支：`feature/user-product-preferences-20261026`（基线 `c00ab8b`）

## 需求一：三个页面按用户账号记忆产品选择

- 每日报价（/）、价格走势（/trends）、数据与报表（/reports）**各自独立**保存产品选择（不是全局共享列表）；
- 每用户独立；跨刷新、退出重登、换浏览器/设备（同账号）恢复；用户间完全隔离；
- 服务端持久化（auth.db），不依赖 localStorage；
- 区分「从未保存过」（页面默认行为）与「显式清空」（记住空选择）；无效/下架产品 ID 安全过滤，不得导致页面加载失败；
- 保存失败有明确提示；恢复顺序 = 先加载可用产品目录，再按已保存 ID 恢复；
- **只持久化产品选择**，不持久化日期范围、搜索词、指标等其他筛选项。

## 需求二：每日报价隐藏无有效报价行

- **两种模式都隐藏**（用户 2026-10-26 明确确认）：默认 40 品种视图 + catalog 多选模式；
- 有效报价判定 = 后端业务口径「average_price 可解析非空」；不伪造报价、不硬编码产品、不删数据/配置/任务；
- 按查询日期（含 as_of 历史日期）的真实有效报价决定展示；全空时显示简洁空状态。

## 需求三：价格走势默认日均价 + 摘要区间均值（口径经用户三轮确认）

1. 首次打开页面默认选中「日均价」指标（现状已默认，补 JS 显式初始化防漂移）；不重置用户已切换的指标；
2. 曲线算法不变：每点 = 该报价日 DB 真实 `average_price`；缺报日期不补值、不造点、不连线；
3. 摘要区「期末日均价」改为「日均价：xxx 元/吨」，**xxx = 区间均值**：
   **所选窗口内有效报价点 `average_price` 求和 ÷ 有效报价点数量（= 实际有报价的天数），不使用自然日总数作分母。**
   用户示例：7 天区间仅 2 个有效点 215000、213500 → 均值 = (215000+213500)÷2 = 214250，而不是 ÷7。
4. 最低价、最高价原有口径不变。

## 非本次范围（保持不变）

登录/注册/邀请码/权限、采集任务与钉钉日报、产品主数据、历史数据与导出、月报与月报默认清单
