# 01 需求确认（2026-10-20）

## 需求来源

钉钉业务报价日报升级任务：在保留原有采集通知能力的基础上，将网站「每日报价」的 40 种 SMM 业务产品价格，以分类明细形式推送到钉钉群。

## 已确认决策

| 项 | 决策 |
|----|------|
| 展示方案 | 方案 C：采集概况 + 40 种业务产品分类明细 + Excel 下载 |
| 顶部统计 | 只保留「采集结果」「全量数据」；正文删除 MySQL 新增/更新等数据库技术统计（内部日志与运维监控保留） |
| 产品范围 | 与网站每日报价相同的 40 种 SMM 业务产品（config/business_products.yaml 中 source=SMM 的 40 行） |
| 缺失产品 | 方案 A：保留位置，标注「本次无新报价」，可附数据库真实最近报价与真实日期；历史也无 → 「本次无新报价，历史暂无有效报价」；绝不制造数据 |
| 下载鉴权 | 公开签名链接（用户 2026-10-20 确认）：新增 /dl/{sig}/{exp}/{path} 免登录限时签名下载 |
| 数据一致性 | 网站与钉钉共用同一套产品映射、同一 SQLite、同一查询函数（portal_service），绝不允许两套口径 |

## 确认的 7 项复述

1. 日报顶部只保留采集结果 + 全量数据，不展示 MySQL 新增、更新条数。
2. 产品范围与网站每日报价使用相同的 40 种 SMM 业务产品映射。
3. 按业务类别（info_category）展示 40 种产品的价格明细，分类与顺序来自现有业务配置（business_products.yaml）。
4. 缺失产品保留位置，标记本次无新报价，可附最近一次真实报价及其真实日期。
5. Excel 保留原有全量数据下载，增加 40 种业务产品报价下载（含当次报价状态列，缺失产品保留在导出结果中）。
6. 网站与钉钉使用同一套产品映射和真实数据查询口径。
7. 技术范围：只改日报生成、业务报价读取与必要的最小下载改造，不重构采集器。
